## easytrader 账户选择能力核查（问答）
- 结论：能选账户，但粒度不同。
  - `miniqmt`：`connect(miniqmt_path=..., stock_account='资金账号')`；当前实现 `StockAccount(stock_account)` 未暴露 `account_type`（miniqmt_trader.py:233），默认普通证券账户，信用/期货账户需改代码。
  - 客户端类（yh/gj/ht/htzq/wk/gf/universal）：`prepare(config_path)` 换配置文件 或 `prepare(user=, password=, comm_password=)` 换参数；一个实例同时只有一个账号。
  - `ths`（`easytrader.use('ths')` → `ClientTrader`）：**没有 login/prepare**，只能 `connect(exe_path)` 接管已手动登录的客户端，账户由手动登录决定；要代码选账号只能用 `universal_client` 的 `prepare(user=...)`（需客户端首次手动登录并勾选保存密码），或为每个账号启一个独立 exe 进程分别 connect。
  - 雪球：按 `portfolio_code` 组合选。
  - 多账户并行：`follower.follow(users=[u1, u2], ...)`。

## 修复 query_ths.py 连接报错
- 现象：`user.connect(exe_path=...)` 抛 `RuntimeError: No windows for that process could be found`。
- 原因：pywinauto `find_elements` 默认 `visible_only=True`，当 xiadan.exe 处于登录框阶段/最小化到托盘/主窗口未就绪时，进程能找到但没有可见窗口。
- 处理：在脚本里加了 `wait_client_window()`——轮询 `findwindows.find_elements(top_level_only=True, visible_only=False)` 按标题 `网上股票交易系统5.0` 找窗口，隐藏则用 `win32gui.ShowWindow(SW_RESTORE)` 还原，最多等 60s，取到 PID 后再 `connect`。已验证本机连接成功（PID 2556）。
- 环境：xiadan.exe 为 32 位，Python 3.11 64 位，会有 bitness 警告；若后续仍莫名连不上，改用 32 位 Python。

- **主窗口内同时存在 5 个 control_id=1047 的 CVirtualGridCtrl**（每页一个，只有当前页可见），easytrader 的 `BaseStrategy._get_grid` 取第一个隐藏的小 grid → 空表 / ElementAmbiguousError。已在 query_ths.py 里用 `VisibleGridWMCopy` 改为"取可见且面积最大的 grid"。
- **该客户端有拷贝/保存双重保护**：WM_COMMAND 复制（WMCopy）和 Ctrl+S 另存（Xls）都会弹"检测到您正在拷贝/保存数据…请先输入验证码"对话框（#32770，图片 Static 0x965、输入 Edit 0x964、确定 Button1、取消 Button2）。触发后会持续拦截，必须识别验证码才能读表。
- UIA 后端读该 grid 返回 0 个子节点（自绘控件），无法绕过复制/保存。
- easytrader 只有 Copy/WMCopy 系列内置验证码 OCR（`grid_strategies._get_clipboard_data`，要求识别结果是 4 位），依赖 pytesseract；本机未装 tesseract。备选方案：ddddocr（pip 包，无需装系统软件）或交互时手动输入（`utils.captcha.input_verify_code_manual`）。

## 验证码全自动识别已打通（tesseract 方案）
- tesseract 其实已装在本机 `C:\Program Files\Tesseract-OCR\tesseract.exe`，只是不在 PATH。`easytrader/utils/captcha.py` 新增 `find_tesseract_cmd()` 自动探测（PATH + 常见安装目录），并重写 `captcha_recognize`：放大 3 倍 + psm 7/8/13 + 字符白名单，返回过滤后的 4 位结果；`invoke_tesseract_to_recognize` 也接入了探测。
- **关键修复（easytrader/grid_strategies.py `_get_clipboard_data`）**：验证码输入原用 `type_edit_control_keys`（该客户端安全控件写不进去 → 永远"验证码错误"），改为 `editor.type_keys(code, pause=0.05)` 真实键盘输入 + 失败降级；提交由回车改为**优先点击确定 Button(control_id=1)**，失败再回车。实测一次通过。
- query_ths.py 最终形态：`VisibleGridWMCopy`（取可见面积最大的 grid）+ `find_tesseract_cmd()` 判断是否需要手动兜底 + `close_copy_captcha()` 兜底 + `drop_empty_rows` 过滤空行 + 每步 `safe()` 包裹。
- 连续两次完整运行成功：资金/持仓/当日委托/当日成交/可撤委托全部正常返回（账户当前无持仓无委托，返回空列表是正常的）。
- 新增 `--strategy` 选项后实测的默认策略输出正常；另加 `current_account()`：从状态栏 Static 读当前登录账号（本机为 `mncg116`），客户端自绘界面 `GetMenu()` 返回 0、无标准菜单，无法自动化点"切换账号"。
- 表格策略做成选项 `--strategy=auto|xls|wmcopy`，默认 wmcopy。实测结论：**本客户端"保存"也受保护**——对 grid 按 Ctrl+S 弹出的不是另存为对话框，而是「检测到您正在保存数据」验证码弹窗（控件与拷贝保护相同：图片 0x965、输入框 0x964、确定=1、取消=2），所以 Xls 策略无速度优势，仅留作备用。另注意 `app.top_window()` 在该客户端返回的是主窗口而非弹窗，定位弹窗要用 `find_elements(process=pid, class_name="#32770", visible_only=True)`。
- 实测跑通：`python -X utf8 query_ths.py` 完整输出（资金 20万 / 可取0 / 市值0，持仓、当日委托、当日成交、可撤委托均为空）。每次读表格都会触发"拷贝保护"验证码弹窗，OCR 自动识别，重试 1~5 次可过，全流程约 25 秒。未装 tesseract 时会降级为手动输入。
